## Profils et bornes conservés

- Quatre en-têtes privés existants : `X-Pro-Key-Id`, `X-Pro-Timestamp`, `X-Pro-Nonce`,
  `X-Pro-Signature`. L’environnement doit être explicite côté serveur, source active et de même
  environnement, scopes relus. Les secrets restent référencés par nom, jamais écrits dans la doc.
- COMMAND signe neuf composants longueur:valeur joints par `|` ; le scope exact lie l’opération.
  Les contrôles privés ajoutent un composant opération et utilisent leur audience propre.
  Préparation liaison : 8 Kio/5min ; COMMAND : 64 Kio/10min ; contrôles : 8 Kio/60s.
- Médias catalogue : requête JSON signée, octets image <=10 Mio, `Content-Length`,
  `X-Content-SHA256`, `nosniff`, garde relue après chargement. Aucune URL privée retournée.
- PDF candidature : `application/pdf`, préfixe `%PDF-`, <=5242880 octets ; signature sur les
  octets exacts. Nouvelle copie fermée par le registre source P16 ; `already_stored` historique
  est distinct d’un nouvel effet.
- PUBLIC sortant : `FEDERATION-INBOX-V1`, timestamp secondes, HMAC hex64 sur
  `environment + LF + timestamp + LF + rawBody`, quatre headers `x-antsia-*` ; destination
  `/federation/inbox` appartient à ANTSIA, pas au routeur PRO.GA. Corps <=128 Kio, reçu <=8 Kio,
  timeout10s, redirections refusées, preuve reçue/appliquée/rejetée distincte. Clé PUBLIC séparée
  de la clé privée ; recette seulement sandbox sous ses gardes, aucune configuration créée.

Ancres de source : `convex/http.ts` ; `packages/pro-domain/src/{integrations,refs,federation}.ts` ;
`commerce/command.ts#commerceCommandSigningInput` ; les huit contrats ciblés à la racine du
paquet domaine ; `integrations/{crypto,transport,inbox,validators,commerceCrypto,commerceConfig,
commerceValidators,commerceTransportConfig,commercePublicTransport}.ts`.
