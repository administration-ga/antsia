## Raccords dans les vraies sources

`apps/antsia_mobile/index.ts` enregistre `src/app.tsx` avec Expo. L'application est un espace de
travail réel, découvert par les outils existants ; aucun HTML indépendant ou écran sans import.
La navigation native monte le fil, une publication, la boîte, une conversation et les réglages.
Le provider racine demeure monté entre ces destinations. Aucun hôte d'appel fictif n'est ajouté.

Les API proviennent exclusivement de `@antsia/api/engine`, les règles de texte et apparence de
`social-contracts`, les gardes serveur existantes restant inchangées. Aucun client Convex PRO.GA
ni import de son schéma. Les types de résultats sont dérivés des API réelles.

### Authentification et données personnelles

- Client Better Auth dédié, transports e-mail/SMS déjà configurés côté moteur. Le header
  bearer émis après une vraie vérification OTP est la seule preuve persistée. Les corps JSON,
  cookies Web et paramètres de liens ne sont jamais adoptés comme session.
- SecureStore : une clé exacte par point d'entrée, file sérialisée bornée, accès
  `WHEN_UNLOCKED_THIS_DEVICE_ONLY`. Réponses tardives invalidées par génération, purge en file
  derrière les écritures natives, erreurs/délais fermant la lecture. Aucun texte de message,
  JWT Convex, CV ou média conservé durablement par ce client.
- SDK `getSession({disableCookieCache:true})`, JWT serveur puis `mySession` du moteur. Le
  `sessionId` reste soumis à la garde Better Auth vivante du backend. Après coupure, les
  données restent masquées pendant une relecture HTTP fraîche de la session et de l'adhésion,
  au lieu de prendre le cache WebSocket comme autorité.
- Aucun profil ou membre créé automatiquement. Inscription/adhésion incomplète ou suspendue :
  accès privé fermé et retour vers le site, avec sortie de session toujours disponible.
- Retour IDN natif non raccordé ; l'interface le dit et distingue connexion Web et native.
  Aucun fichier auth/session existant de l'autre session n'a été modifié.

### Fil et messages

- Fil liste/vertical et publication : pagination par curseur complet, pages réactives,
  dédoublonnage, préparation du fil existante, limites 20 × 10 pages. Une fenêtre vide ou
  lacunaire conserve sa continuation. Fenêtre atteinte annoncée, actualisation manuelle.
- Images/vidéos uniquement depuis le DTO gardé ; retenue ou URL nulle = information de retenue.
  Une seule vidéo active par publication, mise en pause/démontage hors lecture ou hors session.
  Pas de permission caméra/micro ni de lecture en arrière-plan/PiP.
- Boîte et conversations personnelles existantes. Texte via RHF/Zod et limite partagée.
  Intention immuable réseau/personne/session/époque/fil ; même clé et même corps après incertitude,
  aucun rejeu automatique. L'ACK libère le composeur pour un nouveau message. Accusé « lu »
  distinct d'« envoyé », aucune réception sur appareil inventée.
- Hors ligne, contenu masqué et intention encore montée conservée en mémoire. Son abandon
  par navigation/arrière-plan/processus ne garantit aucune reprise durable : le message déjà
  admis par le serveur peut réapparaître dans la conversation. Pas de promesse d'annulation
  d'une écriture déjà partie ni de survie après arrêt forcé.
- Groupes, démarrage d'une nouvelle conversation, dépôts/vocaux, réactions/commentaires
  sortants, commerce et profils natifs complets restent ouverts. Aucun parcours simulé.

### Sortie et apparence

La porte native `packages/social-native/src/sign-out.ts` ferme les gestes avant le premier
await, arrête les ressources, tente révocation globale et sortie SDK avec délais, puis purge
la clé propre au moteur. Le contrôleur remplace le client SDK et démonte le client Convex et
ses caches. Une purge non confirmée garde l'accès fermé ; une révocation globale non confirmée
reste explicitement distincte d'une sortie locale. Le cliquet des sorties inclut cette porte.

`@antsia/ui/themes/antsia-native` projette les rôles actuels des sept chartes en clair/sombre,
sans import DOM/CSS à l'exécution. Sable conserve ses cartes beige ; Gaboma suit sa charte
courante. Les choix locaux n'écrivent pas le compte. Polices système, aucune police embarquée
annoncée. Un scénario de parité avec la cascade CSS est écrit, sans exécution.
